# Goal-Driven Delivery

用于用户提供 plan.md、checklist.md 或明确持续目标/完成约束。保留用户原文与当前完成标准，不从历史案例推导额外需求。

- plan 是方案真源，checklist 是详细进度真源；派发前确认需求点清单，完成一项更新一项。
- 压缩、恢复、换手后先读 plan/checklist 与台账，再行动；发现方案矛盾先记录并升级，不能机械勾选。
- project-goal 始终保存目标；工具级 goal 仅在用户明确要求且可用时创建，不覆盖已有目标或发明预算。
- 实施保持高内聚低耦合，先验证外部 API/SDK/契约再依赖其实现；跨边界真实联调按风险做。
- 文件行数、文件头、逐目录 README 等约束仅在用户当前要求或项目规范规定时实施；不能因启用本模式就重构全仓、批量补文档。
- 文档保持少而准确；临时产物放任务目录，只清理本任务且获授权的内容，不删除用户记录。
- PR 默认按完整交付单元规划，不按任务编号碎片化。
- 完成标准以用户当前约定为准；默认真实用户旅程通过并达到人工验收状态。部署、发布、压测只在目标、依赖或风险确实需要且有授权时成为条件。
- 目标包含 PR/review/合入时治理到对应实际状态，不能说 PR 创建就完成；证据缺失保持 pending/blocked。
- 形式验收记录绑定 clean head；后续改 head 要检查差异并重验受影响路径。人工验收延续按 `engineering-delivery/references/acceptance-continuity.md`，保留真实历史观察，遵守明确的人工/精确 SHA 门禁。
