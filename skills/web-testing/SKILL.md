# Web 综合验收

输出基于实际运行的验收结果。用户给出的范围、环境与授权决定测试边界；只请求验收时报告问题，明确要求修复时才改产品代码。

## 统一执行流程

1. 确认目标 URL、仓库/构建版本、用户角色、核心旅程和验收标准。优先从当前任务和项目说明获取。未指定范围时，从变更涉及的主要旅程开始；不要默认最后一个 commit 就是测试范围。已有服务需核对实际版本，HTTP 200 不代表页面正常渲染。
2. 发现当前可调用浏览器工具及已安装 CLI；注册配置不等于本会话已加载工具。读当前工具 schema 或 CLI help。选择一个工具和隔离会话执行主流程，避免用多个浏览器重复同一组测试。复用登录态必须符合任务授权，不能自行导出凭证或上传 cookie。
3. 建立简短矩阵：用例 ID、前置状态、动作、预期、检查维度、证据。合并正常路径、异常恢复、边界输入、快速重复操作和视觉/无障碍覆盖。按风险选取相关场景，不机械执行无关清单。
4. 逐条观察 → 操作 → 再观察 → 断言。定位依据最新 DOM/无障碍树；界面变化后重新获取引用。用可观测状态等待，不靠长时间 sleep。验证用户可见结果和必要的网络/服务持久化结果，成功 toast 不单独证明保存成功。
5. 对改变的视觉状态读 [视觉与状态检查](references/visual-and-state-checks.md)，保存实际截图并查看；动画问题补录屏或连续帧。性能疑点才采集 trace，记录测量条件与对照。
6. 如要求固化回归，优先接入项目现有 Playwright 测试及报告机制；先确认真实流程可执行，再写稳定断言。明确 mock 和真实后端覆盖。修复后复跑失败用例与受影响邻接流程。
7. 保存中文报告与证据，按下方格式交付。仅关闭本次创建的会话、进程和设备连接。

## 工具分工

| 目的 | 首选能力 | 降级方式 |
|---|---|---|
| 真实浏览器交互、探索验收 | 当前会话浏览器工具，或 browse CLI | Playwright CLI/MCP |
| DOM、样式、Console、请求、性能定位 | Chrome DevTools MCP | 当前浏览器支持的等效观测；缺失部分列为 BLOCKED |
| 可重复 E2E、截图基线、跨浏览器 | 项目 Playwright 套件 | 先交付实际探索证据，注明尚未固化 |

此入口自包含，不依赖其他测试 Skill。通过当前工具 schema、CLI help 和项目测试配置选择执行方式，不强制并行或云浏览器。环境缺少浏览器驱动时报告安装需求，不自动改全局配置。

## 报告和证据

使用项目既有产物目录，否则创建本次独立的临时证据目录并返回绝对路径，不假设某个目录已被 gitignore。

- 概况：目标、版本、浏览器、viewport/DPR/zoom、环境/角色、真实后端或 mock、范围。
- 用例表：ID | 旅程/状态 | 预期 | 实测 | PASS/FAIL/BLOCKED/SKIPPED | 证据路径。
- 问题表：严重度 | 复现步骤 | 用户影响 | 预期/实际 | 截图/trace/日志 | 修复建议。
- 结论：范围内通过、发现问题或验收不完整。分别给出各状态数量；BLOCKED/SKIPPED 不计作通过，注明未覆盖项。

PASS 必须对应实际观察。截图只能证明截图覆盖的视觉状态；DOM 正确不自动证明视觉正确。区分“用例已写”“测试已跑”“真实环境已验收”。没有截图时仍可报告行为失败，但注明视觉证据缺失。基线差异未经确认不自动更新基线。报告中的个人信息和凭证脱敏。

测试数据创建/编辑应限于任务授权账号和环境；删除真实数据、支付、对外发送或上传云服务需要已有明确授权。不能通过给 browse 增加全局权限、自动切换分支、重置数据来解决验收障碍。
